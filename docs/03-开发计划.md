# 开发计划

## 当前状态

该文件保留最初的阶段计划。应用已按用户后续指示完成第一版本地实现；实际交付和验证见 [实现与验证记录](05-实现与验证.md)。下列任务用于说明后续维护与升级方向。

## 阶段 1：上游审查与最小算法验证

任务：

- 固定上游提交，取得代码、数据及 MIT 许可，记录来源。
- 阅读完整筛选与分类代码，核对数据生成规则和完整性论证。
- 运行上游测试与默认验证，独立复算代表性边界。
- 核验默认／严格规则关系、单等号反例数据和多等号分类数据的适用范围。
- 测量代表性 8–15 位搜索的时间和内存，确认核心搜索是否足以支持第一版。

交付物：上游版本记录、验证报告、性能基线、需要修复或适配的问题清单。

完成条件：明确哪些结论可以直接查表、哪些要重新计算，以及第一版性能的实际范围。若普通精确搜索不适用，先调整技术设计再做界面。

## 阶段 2：计算引擎

任务：

- 实现统一输入、规则与结果模型。
- 接入查表判定与精确搜索，并分别记录存在性和搜索完成状态。
- 扩展为每个值保留多条表达式；完成去重、排序和逐步返回。
- 实现独立的语法、数字保留和分数求值验证。
- 生成素可归零串见证与索引，核验覆盖性。
- 实现至少 16 位整数的归零构造及多种构造选择。
- 加入进程隔离、取消、搜索预算和有限缓存。

交付物：可独立调用的 Python 引擎、已验证派生资源、针对数学正确性和状态语义的测试。

完成条件：任何输出的等式都合法；任何“无解”都有完整依据；取消或超时不会被当作无解。短串精确判定与独立参考枚举一致。

## 阶段 3：本地网页与任务服务

任务：

- 制作整数输入、规则选择、方案数量、结果卡片与复制操作。
- 接入异步任务、结果轮询、取消与继续搜索。
- 清楚展示查表／定理／见证／穷举的不同依据。
- 实现本地启动、端口冲突提示和关闭后的任务清理。
- 检查键盘操作、手机宽度布局和中文可读性。

交付物：能在本机浏览器使用的第一版应用和启动说明。

完成条件：需求文档中的案例可以通过页面完成；长任务不会冻结页面；离线运行不请求外部资源。

## 阶段 4：验证、性能与交付

任务：

- 对每条样例执行独立验证；进行有固定种子的随机输入检查。
- 对短串进行完整枚举对照，覆盖默认／严格规则及单／多等号。
- 验证长整数构造在 16、64、256 位及包含大量零的输入上保持数字完整。
- 验证多方案去重、实际数量不足、连续提交、取消和资源上限。
- 测量 8–15 位困难输入，优化缓存与搜索顺序并明确运行限制。
- 保留第三方许可与版本，编写离线使用及故障说明。

交付物：测试报告、性能报告、用户说明与可运行目录。

完成条件：正确性、资源状态、页面交互和离线运行均通过；性能承诺只采用实际测得的结果。

## 后续可选阶段

- 打包 Windows 桌面程序，减少手动启动步骤。
- 支持批量整数输入和导出结果。
- 纯 HTML／Web Worker／BigInt 版本，需要重新评估计算性能和规则一致性。
- 研究 8–15 位输入的更快构造方法，以及其他进制或符号集。

## 主要风险与处理

| 风险 | 处理 |
|---|---|
| 8–15 位精确值集过大 | 提前测量；优先查表和快速见证，限制预算，必要时改进算法 |
| 多方案导致内存增长 | 限制每个值的见证数量，区分见证截断与值集截断 |
| 规则不同导致错误分类 | 默认／严格模式独立验证，不直接套用含负号见证 |
| 数据未覆盖全部输入或发生遗漏 | 记录范围，审查筛选完整性，依据不足时保留“未知” |
| 长整数计算爆炸 | 用已核验归零见证构造，避免完整长串值集枚举 |
| 上游生成或验证代码有缺陷 | 独立语法与分数验证，保留来源，修复需附回归案例 |

暂不给出固定工期。阶段 1 的性能与数据审查结果决定后续开发规模；按阶段验收推进，避免在算法能力尚不明确时承诺界面性能。

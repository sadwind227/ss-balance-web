# 实现与验证记录

日期：2026-10-08。本文记录在规划文档之后完成的实际实现。

## 已实现的行为

- 本地浏览器页面：整数输入、等号数量、规则模式、目标数量、示例、取消搜索、复制等式。
- 仅绑定 `127.0.0.1` 的 Python 服务；任务在独立子进程中运行，通过 JSON 文本流逐条回传已验证方案。
- 上游反例表与分类表查阅；未知严格多等号例重新进行精确搜索。
- 16 位及以上整数使用素可归零子串构造，可通过不同子串及归零表达式给出多条方案。
- 2–7 位按精确值表搜索，可达值不因见证数量限制而截断；8–15 位先尝试归零构造，再搜索单等号方案。
- 独立 AST 白名单验证器检查运算、负号位置、数字保留、除零与各等号段精确相等。
- 每次搜索有 30 秒时限，可选择延长到 90 秒；值表每段 150000 个值的保护上限会让状态显示“搜索未完成”。

相较最初技术设计，后台计算改为 `subprocess` 文本流，因为当前 Windows 环境不允许 `multiprocessing.Queue` 使用的命名管道。归零见证按需生成并缓存，不预先生成全部 6534 条素可归零见证。

## 已知限制

- 8–15 位中较困难的数字，或请求很多方案时，搜索可能达到时间／值表上限；存在性与见证生成状态会分别显示。
- 多种方案按表达式写法去重；它们可能共用同一个归零子串或数学原理，软件不保证语义上完全独立。
- 256 位输入上限、最多 20 条方案是当前版本的产品设置。
- 当前应用面向个人本机使用，已提供 Windows 64 位独立程序压缩包；没有公开服务器部署。打包验证见 [打包记录](06-打包记录.md)。
